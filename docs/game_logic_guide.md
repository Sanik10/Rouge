# 🎮 Объяснение логики боевой системы игры (для новичков)

> Привет! Этот файл объясняет, как работает боевая система нашей игры. Даже если ты только начал учить Java, после прочтения ты поймёшь, что здесь происходит.

## 🎯 Самое главное в одном предложении

**Игрок и враги ходят по очереди: игрок ходит, потом враги реагируют. Если они столкнулись — начинается боевой раунд!**

---

## 📚 Базовые концепции (для новичков)

### Что такое `GameState`?

Представь, что `GameState` — это **шкаф с информацией о игре**.

```
GameState = {
  "Игрок где находится?": (5, 5),
  "Игрок жив?": true,
  "HP игрока": 100,
  "Враги в игре?": [Вампир, Зомби, Привидение],
  "Размер карты": 10x10
}
```

Когда что-то меняется в игре (игрок двигается, враг получает урон), мы обновляем эту информацию в `GameState`.

### Что такое `Enemy`?

Враг — это объект, у которого есть:

```
Enemy = {
  "Тип": VAMPIRE,
  "HP (здоровье)": 25,
  "Сила атаки": 8,
  "Позиция": (5, 4),
  "Особые способности": FirstHitIgnoredSpecial
}
```

## 🔄 Один игровой раунд (как это всё работает)

### Этап 1: Игрок делает ход 📍

```
┌─────────────────────────────┐
│ 1. Игрок нажимает клавишу   │
│    (стрелка вверх)          │
└──────────────┬──────────────┘
               │
               ↓
       ┌───────────────┐
       │ Вычисляем:    │
       │ Куда идти?    │
       │ (5,5) → (5,4) │
       └───────────────┘
               │
               ↓
   ┌───────────────────────┐
   │ Проверяем:            │
   │ Там враг?             │
   │ Да! Вампир в (5,4)   │
   │ → АТАКА! 💥          │
   └───────────────────────┘
               │
               ↓
   ┌──────────────────────────┐
   │ Урон = 15               │
   │ Вампир получает урон    │
   │ HP: 25 → 11             │
   └──────────────────────────┘
```

**Важно**: Если игрок попал в врага, **ход потратился** и враги сейчас ответят!

### Этап 2: Враги реагируют на ход игрока 👹

После того как игрок ходит, **каждый враг** делает свой ход:

```
Вампир (в 1 клетке от игрока):
  ├─ Видит ли он игрока? ДА (расстояние ≤ его видимость)
  ├─ Может ли атаковать? ДА (рядом, на соседней клетке)
  └─ ВАМПИР АТАКУЕТ! Урон = 8, HP игрока: 100 → 92

Зомби (в 2 клетках):
  ├─ Видит ли он игрока? ДА
  ├─ Может ли двигаться туда? НЕТ (там уже вампир)
  └─ ЗОМБИ ОСТАЁТСЯ НА МЕСТЕ

Привидение (далеко):
  ├─ Видит ли он игрока? НЕТ (слишком далеко)
  └─ ПРИВИДЕНИЕ ХОДИТ СЛУЧАЙНО
```

---

## 🤝 Что означает "одна клетка рядом"?

Есть два способа считать расстояние:

### 1️⃣ Manhattan Distance (для видимости врага)

"Видит ли враг игрока издалека?"

```
Враг в (5,4), Игрок в (5,5)

расстояние = |5-5| + |4-5| = 1
если (1 <= видимость врага) ДА, видит!
```

Представь, что враг видит в крестообразной форме: вверх, вниз, влево, вправо.

### 2️⃣ Chebyshev Distance (для соседства)

"Может ли враг атаковать игрока?"

```
Враг в (5,4), Игрок в (5,5)

расстояние = max(|5-5|, |4-5|) = 1
если (расстояние == 1) АТАКУЙ!
```

Враг может атаковать, если находится на 1 клетку в любом направлении (даже по диагонали).

## ⚔️ Раунд боевой системы по шагам

Представь, что происходит внутри метода `step()`:

```java
step(Command cmd) {
  // ШАГ 1: Игрок ходит или атакует
  boolean playerActed = gameState.tryMovePlayer(UP);
  // → Вычислили новую позицию (5,4)
  // → Там вампир? ДА!
  // → playerAttackEnemy(vampire) ← внутри!
  // → playerActed = true

  // ШАГ 2: Если игрок потратил ход, враги реагируют
  if (playerActed) {
    // ШАГ 2.1: Обновить состояние игрока
    gameState.afterPlayerTurn();
    // → gameState.player.tickSleep();
    // → (если была магия сна, уменьшить счётчик)

    // ШАГ 2.2: Враги ходят
    gameState.enemiesTurn();
    // → for each enemy:
    //   - Враг смотрит: видит ли он игрока?
    //   - Если ДА: идёт к игроку
    //   - Если НЕТ: идёт случайно
    //   - Проверить: рядом ли с игроком?
    //   - Если рядом: АТАКУЙ ИГРОКА!

    // ШАГ 2.3: Увеличить счётчик раундов
    turn++;
  }

  // ШАГ 3: Вернуть результат для экрана
  return new GameSnapshot(playerX, playerY, turn, log);
  // → На экран попадёт вся информация о раунде
}
```

## 🎁 Специальные способности (EnemySpecial)

Некоторые враги имеют **специальные способности**. Это как магические умения!

### Пример 1: FirstHitIgnoredSpecial (Вампир)

**Что это?** Первый удар игрока по вампиру не наносит урона!

```
РАУНД 1:
  Игрок атакует: урон 15
  Вампир использует FirstHitIgnored:
    → "Ну нет! Первый удар я блокирую!"
    → Вампир получает 0 урона вместо 15
    → HP остаёт 25/25

РАУНД 2:
  Игрок атакует: урон 14
  Вампир использует FirstHitIgnored:
    → "Я уже использовал эту защиту!"
    → Вампир получает 14 урона
    → HP: 25 → 11
```

### Пример 2: VampireDrainSpecial (для вампира)

**Что это?** Когда вампир атакует, он восстанавливает себе часть здоровья (питается кровью).

```
Вампир атакует игрока:
  → Урон = 8
  → Вампир получает 4 HP обратно (50% от урона)
  → HP: 11 → 15
```

## 📍 Как враги двигаются?

### Случай 1: Враг видит игрока

```
MAP:
V . . .  ← Вампир (0,0)
. . . .
. . . P  ← Игрок (3,3)

Расстояние по Manhattan = |0-3| + |0-3| = 6
Видимость вампира = 8
6 <= 8? ДА, видит!

Вампир делает шаг ближе:
  Нужно идти вправо И вниз одновременно
  → Он идёт либо вправо, либо вниз (один шаг)
  → Новая позиция: (1,0) или (0,1)
```

### Случай 2: Враг НЕ видит игрока

```
MAP:
V . . .  ← Вампир (0,0)
. . . .
. . . .
. . . .
. . . P  ← Игрок (4,4)

Расстояние = |0-4| + |0-4| = 8
Видимость вампира = 3
8 <= 3? НЕТ, не видит!

Вампир ходит СЛУЧАЙНО:
  → Выбираем случайное направление
  → Движемся в нём
  (типа враг блуждает в потёмках)
```

## 🔄 Как данные хранятся? (Синхронизация)

Это **очень важно** понять для новичков!

### Проблема, которую мы решили:

Раньше могла быть ситуация, когда информация "разъезжается":

```
❌ НЕПРАВИЛЬНО:
  GameState говорит: "Игрок в (5,5)"
  Player объект говорит: "Я в (5,4)"
  КТО ПРАВ? Хаос! 🔥
```

### Как мы это исправили:

```
✅ ПРАВИЛЬНО:
  GameState СОДЕРЖИТ Player объект
  Player { x=5, y=5 }
  GameState { playerX=5, playerY=5, player=... }
  
  Когда игрок движется:
    → player.moveTo(5,4)  ← обновляем объект
    → gameState.playerX = 5, playerY = 4  ← синхронизируем
    
  ВЫВОД:
    gameState.player.getX() == gameState.playerX  ← ВСЕГДА!
```

Это значит, что у нас **одно место истины** (source of truth).

## 💡 Почему это сделано именно так?

### 1. Clean Architecture

**Слои разделены**:
- **Presentation** (экран) — показывает информацию
- **Use Case** (engine) — логика игры
- **Domain** (GameState, Enemy) — данные о мире

Так код не путается — каждый слой знает только о своём.

### 2. Immutability (неизменяемость)

**GameSnapshot не может измениться** после создания. Это хорошо, потому что:
- Легче найти баги (когда всё меняется, сложнее отследить)
- Нет неожиданных побочных эффектов

### 3. List<Enemy> вместо отдельных врагов

**Хранить врагов в массиве** позволяет нам:
- Легко добавлять новых врагов
- Легко проверять всех врагов в цикле
- Легко удалять мёртвых врагов

## 🎓 Ключевые термины (словарик)

| Термин | Значение |
|--------|----------|
| **GameState** | Объект, который хранит всю информацию об игре (позиция игрока, враги, HP) |
| **Enemy** | Объект, который представляет врага (тип, HP, позиция, способности) |
| **EnemySpecial** | Специальная способность врага (например, блокировка первого удара) |
| **Command** | Команда от игрока (Move up, Wait, Attack) |
| **GameSnapshot** | Снимок состояния игры (результат одного хода) |
| **Hostility** | Насколько далеко враг видит игрока |
| **Manhattan Distance** | Способ считать расстояние для видимости |
| **Chebyshev Distance** | Способ считать расстояние для атаки |
| **tick()** | Обновить состояние врага (внутренние процессы, вроде восстановления HP) |

## ❓ FAQ (Часто задаваемые вопросы)

### Q: Почему враг не двигается через другого врага?

**A:** Перед движением врага мы проверяем: есть ли там уже другой враг? Если ДА — враг остаётся на месте (или идёт в другую сторону).

```java
if (getEnemyAt(newX, newY) != null) {
  // Там уже враг! Не двигаемся
  return;
}
```

### Q: Что если враг и игрок на одной клетке?

**A:** Это нормально! Значит враг прошёл через позицию игрока... хм, это может быть баг 🐛. Но в коде мы проверяем, может ли враг атаковать ДО того, как двигаться.

### Q: Почему враги ходят ПОСЛЕ игрока?

**A:** Потому что игрок совершает действие ПЕРВЫМ, а враги **реагируют** на его действие. Это справедливо в тактических играх.

```
Правильный порядок:
  1. Игрок ходит
  2. Враги видят, что произошло
  3. Враги реагируют
```

### Q: Может ли враг атаковать, если он находится на той же клетке что и игрок?

**A:** Хороший вопрос! Мы используем `Chebyshev Distance == 1`, поэтому если враг находится на той же клетке (расстояние 0), он НЕ атакует. Это баг в текущей системе!
