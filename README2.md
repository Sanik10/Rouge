# Crawl (караул)

## Технологии
- Java 21
- Gradle (Kotlin DSL)
- JCurses (рендер и ввод с клавиатуры)
- JSON сохранения/загрузка (конкретную библиотеку определим позже)

## Структура проекта
Проект придерживается стандартного Gradle layout: исходники в `src/main/java`, тесты в `src/test/java`, ресурсы в `src/main/resources`, сборка — в `build/`.

Пакеты (первый уровень):
- `ru.crawl.app` — точка входа, сборка приложения
- `ru.crawl.domain` — бизнес-логика игры (не знает про JCurses и JSON)
- `ru.crawl.presentation` — UI (JCurses): рендер, чтение клавиш, экраны
- `ru.crawl.datalayer` — сохранение/загрузка/таблица рекордов (JSON)

## Архитектура
### 1) Clean Architecture (границы и зависимости)
- Domain — центр системы: там все правила игры и сущности.
- Presentation и DataLayer — внешние слои: они подключаются к домену, но домен не импортирует их классы.
- Интеграция через интерфейсы: домен объявляет контракты (ports), внешние слои дают реализации (adapters).

### 2) MVP в presentation (организация UI)
- View: тонкая оболочка над JCurses (чтение клавиш + отрисовка).
- Presenter: управляет экранами/режимами (игра, инвентарь, статистика), переводит нажатия в команды, вызывает доменный движок, отдаёт данные на рендер.
- Model: доменный слой (GameEngine + GameState).

## Что пишем (обязательная часть 0–5)
### Domain
- Модель мира: Player, Enemy (5 типов), Item, Inventory, Level, Room, Corridor, координаты/клетки.
- Turn-based цикл: “команда игрока → обновление мира → ход врагов”.
- Бой: шанс попадания (ловкость), урон (сила + оружие), смерть, лут (сокровища).
- Генерация уровней: 9 секций (3×3), комнаты случайного размера/позиции, коридоры, проверка связности, старт/финиш.

### Presentation (JCurses)
- Рендер карты (стены/пол/коридоры), акторов (герой/враги/предметы), UI панелей.
- Управление: WASD + клавиши использования предметов, меню выбора (1–9 / 0–9 для оружия).
- Туман войны и поле зрения (ray casting/Брезенхэм).

### Data layer (JSON)
- Сохранение прогресса после уровня: номер уровня + статистика.
- Загрузка последней сессии: восстановление состояния вплоть до позиций/характеристик сущностей.
- Таблица рекордов: сортировка по сокровищам.

## Основные интерфейсы (план)
- `domain`:
  - `GameEngine` — `step(Command): GameSnapshot`
  - `Command` — действие игрока (Move/Use/Equip/OpenMenu/ConfirmSelection)
  - `SavePort` (интерфейс) — сохранить/загрузить состояние/рекорды
- `presentation`:
  - `GamePresenter` — главный цикл, управление экранами
  - `CursesView` — рендер и чтение клавиш
- `datalayer`:
  - `JsonSaveAdapter` — реализация `SavePort`
